# Internal Microservice Catalog & Health Portal

## Problem Statement #42

This repository contains the Requirements Engineering and UML deliverables for the **Internal Microservice Catalog & Health Portal**.

The portal is an enterprise developer portal intended to:

- Map microservice dependencies.
- Aggregate API documentation.
- Periodically check microservice health.
- Record service downtime and send downtime alerts.

## Actors

The use-case model contains:

1. **DevOps Engineer**
2. **System Architect**
3. **Monitored Microservice**

The first two are the target stakeholders identified in Problem Statement #42. The Monitored Microservice represents the external service whose health endpoint is checked by the portal.

## Requirements

The requirements specification contains:

- **FR-001 to FR-005** — 5 Functional Requirements
- **NFR-001 to NFR-002** — 2 Non-Functional Requirements

Key requirements include health monitoring every 30 seconds, dependency mapping, API documentation aggregation, downtime alerts after three consecutive failed health probes, and support for an interactive dependency graph containing up to 200 services.
